## Package API verification

At initial planning, installed-package verification was unavailable. Bootstrap subsequently installed dependencies. Local inspection during implementation on 2026-11-14 confirms **wavesurfer.js 7.12.12 and Tone 15.1.22**. Regions declarations and Tone Offline/GrainPlayer declarations plus implementations were rechecked in the assigned DSP session; see its implementation log below. No installation or manifest/lockfile mutation was performed by WS4.

To make the design reviewable meanwhile, checked the matching published upstream source:

- [wavesurfer 7.12.12 Regions source](https://github.com/katspaugh/wavesurfer.js/blob/7.12.12/src/plugins/regions.ts): `RegionsPlugin.create()`, `addRegion({start, end, drag, resize, ...})`, `getRegions()`, `clearRegions()`, and `enableDragSelection(options, threshold?)` are available. The latter returns cleanup. Use `region-created` for completed drag creation and `region-updated` for finished adjustments; individual regions emit `update-end`. `start === end` is a marker. Selection changes update UI state only; toolbar actions commit ops. Dispose subscriptions, drag selection, and the plugin on unmount. Import via `wavesurfer.js/dist/plugins/regions.esm.js`; verify the package export path locally.
- [wavesurfer 7.12.12 Timeline source](https://github.com/katspaugh/wavesurfer.js/blob/7.12.12/src/plugins/timeline.ts): intervals are seconds, not musical units. Set `timeInterval = 60 / bpm`, `primaryLabelSpacing = 4`, and `formatTimeCallback` for bars/beats. Assume 4/4 for display only; do not invent downbeat metadata. Use seconds when BPM is unknown. Recreate the timeline configuration when the effective tempo changes.
- [Tone 15.1.22 Offline source](https://github.com/Tonejs/Tone.js/blob/15.1.22/Tone/core/context/Offline.ts): `Offline(callback, duration, channels = 2, sampleRate = currentContext.sampleRate)` returns `Promise<ToneAudioBuffer>`; callback may be async and receives `OfflineContext`. Always pass 44100 and the required channel count. Create/connect/schedule nodes inside the callback, start at offline time zero, then copy the returned buffer to PCM. It temporarily switches Tone's global context: serialize Tone offline jobs and dispose nodes after completion; do not overlap them with other Tone graph construction.
- [Tone 15.1.22 GrainPlayer source](https://github.com/Tonejs/Tone.js/blob/15.1.22/Tone/source/buffer/GrainPlayer.ts): accepts an already decoded `AudioBuffer`; `detune` is cents, `playbackRate` independently controls grain progression, and `grainSize`/`overlap` control granulation. Choose GrainPlayer for both duration-preserving pitch shift and pitch-preserving tempo fit. This follows the contract's granular requirement and avoids PitchShift effect latency. Schedule an explicit stop and exact output duration; validate grain edges by listening in Chrome.

## Final decisions (handoff §5)

| Decision | Final choice |
| --- | --- |
| Engine core | Keep plain `PcmBuffer = { sampleRate: number; channels: Float32Array[] }`. Owned, immutable-by-convention channel arrays of equal length; internal engine rate is 44100. Convert AudioBuffer only at browser boundaries. Generated API types remain the wire types. |
| Evaluation | Keep source replay and prefix memoization. Necessary API refinement: `evaluate(sources, state, context): Promise<Evaluation>` because OfflineAudioContext and Tone rendering are async. `Evaluation.buffers` is the recommended clip-ID map, with separate leaf/order/timing metadata. Cache by source identity/version, op prefix, beat/BPM inputs, sample rate and engine version. Structural sharing preserves unaffected buffers; cache is bounded, and stale UI revisions cannot publish results. |
| Web Audio ops | Keep OfflineAudioContext for repitch, filter, and non-pitch-preserving stretch; GrainPlayer inside Tone.Offline for pitch shift and keep-pitch stretch. Repitch rate `2 ** (semitones / 12)`, length approximately `inputFrames / rate`. Tempo ratio `targetBpm / sourceBpm`, duration `inputDuration / ratio`. Pitch shift uses `detune = 100 * semitones`, rate 1; keep-pitch tempo fit uses detune 0, rate ratio. Other ops are pure TS. Fixed output frames are computed before rendering. |
| Slicing | Keep equal-count candidates snapped to nearest mapped beat/onset, explicit `at[]`, or equal parts for `none`. Preserve endpoints; reject collapsed, duplicate, out-of-range or unsorted cuts instead of silently changing child count. Exactly one of count/at is required locally. Children are 1-based and inherit the parent's buffer at that exact chain position. Track beat positions through trim, reverse, rate changes, slice and loop; detect transients on current PCM. No BPM: disable beat mode per handoff, offer none/transient without silently changing a requested op. |
| Undo/redo | Keep op suffix removal, grouped chat batches, and redo invalidation on new edits. Selection is UI state. Source additions use a history checkpoint for the clips list as well, so undo cannot leave references to a removed source. Wire `ops` stays flat; no history metadata goes to `/assist`. Display plain-language history. |
| Waveform | Keep wavesurfer v7 showing rendered active leaf with Regions selection and marker overlays; Timeline labels derive from effective clip tempo when known. Slice result selects a child; lane shows sibling boundaries/order. Feed rendered PCM peaks/duration rather than fetch/decode the source again. Wavesurfer is visual only; never run its own playback alongside engine playback. |
| Arrangement lane | Keep horizontal dnd-kit sortable tiles. A tile has a unique UI occurrence ID even when clip IDs repeat. Drag/drop and duplicate button produce a full `arrange` op; the button is the initial duplicate interaction (Alt-drag optional polish). Clips concatenate with no gaps. |
| Playback | Keep AudioContext + a fresh AudioBufferSourceNode on full arrangement render; playback loop toggle is transport state, separate from the destructive-length `loop` op. Create/resume context on user gesture. Sync active clip cursor through occurrence offsets; repeated clips highlight the currently playing occurrence. Stop before committing a new rendered revision. |
| Controls | Keep the full recommended toolbar: Trim, Slice 2/4/8/16 and snap, Reverse, Repitch ±12 UI (accept contract ±24), advanced Pitch shift, Fit to BPM, Gain, Fade in/out, Normalize, Loop ×, high/low-pass. ## Replay rules and explicit assumptions

- Root `clips` contains sources; slice descendants are derived by replay, not added as new roots. Source arrays are never mutated. Reject missing clip IDs and all targeted ops on sliced parents with `clip_is_sliced`. A later slice can target a leaf child and produce hierarchical IDs.
- Trim and `slice.at` refer to current rendered clip seconds. Use half-open frame ranges with one consistent seconds-to-frame rounding rule; durations may differ by at most one frame from continuous formulas. Never reorder ops: fade then reverse must differ from reverse then fade.
- Start replay from a baseline arrangement in `state.arrangement`; an `arrange` op replaces it. Keep that baseline separate from the derived final order, so undoing an arrange restores the previous order. Do not write the derived final order back into the baseline. Empty baseline means final leaves in creation order. Pending WS2 confirmation, slicing an explicitly arranged parent replaces each occurrence in place with its children; reject newly requested arrangements that reference non-leaves. Repeats remain repeats.
- `loop` materializes repetitions at that point in replay; later trim/fade acts on the resulting longer buffer. Rendering concatenates without inserted gaps/crossfades or implicit normalization.
- Keep source BPM/beat metadata per root in runtime context. All `stretch_to_bpm` ops use that root's track BPM per contract wording, rather than a guessed arrangement BPM. Repeated tempo fits and mixed-source tempo reporting need WS2 agreement below.
- Limit input windows and resulting preview/export to 60 seconds with a clear validation message. Preflight duration and allocation before loop/repitch/arrange, including repeated occurrences; never silently truncate. This is a client resource limit, not a new shared-schema maximum.

## `lib/audio` module design

Public engine modules do not import React, Zustand, wavesurfer or API networking. Browser adapters are imported only from client code. Reuse generated `ClipSource`, `Clip`, `Op`, `EditorState`, `TrackDetail` and `Stem` types; do not recreate the wire schema.

| `ops.ts` | `trim`, `reverse`, `gain`, `fadeIn`, `fadeOut`, `normalize`, `loop`; pure PCM in/out | Node: sample-exact operations, duration, silence, fade clamping/zero length, unchanged inputs, order sensitivity |
